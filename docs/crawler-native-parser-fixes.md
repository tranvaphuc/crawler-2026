# Native response parser repairs (2026-10-27)

Facebook comment badge `serialized` JSON contains numeric `comment_id` values above JavaScript's safe integer limit. Parsing these as numbers rounded the comment ID and discarded valid `actor_id` proofs. `parseFacebookIdentityPayload` preserves ID tokens as strings. Actor resolution checks native author fields, deferred/mirror projections, comment-bound badge payloads across renderer layouts, matching profile facts, then batched public profile routes. It never treats a parent post owner or mentioned user as the comment author. Verified mappings are retained in `flow_author_identities`.

Page collaborations select the verified source profile from `story.actors`; they no longer blindly select the first collaborator. For Facebook user posts tagging an inventory source, `bindFacebookUserPost` assigns the actual native author to `siteId`, `siteName`, `authorId`, `author` and the canonical buzz ID. The inventory source remains in `discoveredFromSourceId`; it is not rewritten or expanded into a new crawl inventory.

Instagram's exact time is read from its bound media projection, including `xig_polaris_media.if_not_gated_logged_out.taken_at`. YouTube uses the matched native player's `publishDate`, falling through to other exact native timestamps when necessary. For these source post timestamps, date-only and relative labels are not converted into invented exact times.

The previous implementation held an entire native page while hydrating every item's metadata. Streaming source delivery now emits dated items immediately, persists emitted IDs through checkpoint restart and keeps the native cursor pending until that page is finished. A second page can stop on its first confirmed old item without waiting for remaining metadata. Source/comment Mongo feeders run independently so a slow channel does not hold another channel's job supply.

The import worker also enriches historical failed payloads from verified response/profile evidence before validating. Repair runs back up original failed jobs in `flow_import_repair_backups`, store repaired fields in `flow_import_repairs`, and retry a bounded sliding window of ten tickets. Posts whose recovered publication date is already outside the approved 72-hour source window complete without importing stale data. Failed jobs with unverified data remain inspectable.

Validation includes raw-response replay for the native badge author, gated Instagram timestamp and timezone-qualified YouTube publication time, plus regression tests for cross-worker streaming, exact long IDs, batched route fallback, page collaborators and tagged user field mapping.

The historical ES5 author repair tool verifies a previously imported canonical comment against its exact index/type/ID, site, publication time, parent ID/date, author name, text, URL and reply parent before reusing its numeric author ID. `repair_existing_import_authors.mjs` audits all matching failed tickets, backs up the original data, records the proof and retries repaired tickets. Historical repair controllers accept error/platform filters and a bounded concurrency so timestamp recovery can progress alongside Facebook author recovery.

Legacy ES5 comment URLs (`/owner/posts/post?comment_id=post_comment`) are compared by verified native IDs against the newer `/owner_post?comment_id=comment` form. Equivalent Instagram `p`/`reel` URLs are similarly matched by shortcode; different IDs, authors or content still prevent reuse. Verified historical post counters are restored along with publication time so eligible posts can supply comment jobs.

`repair_native_import_publications.mjs` rehydrates missing dates and counters from the exact native post response, checks both post and source-author IDs, rotates proxies up to 50 retries and stores request outcomes in `flow_import_repair_attempts`. `repair_native_import_authors.mjs` groups failed comments by parent post, checks exact comment/date/name projections in HTML and GraphQL, then resolves public profile routes. The ES5 worker performs no author lookup or author repair. Native recovery runs in the separate repair tools, so malformed historical jobs fail promptly and cannot starve valid imports. Absent numeric authors still fail validation and remain visible. Page collaborator recovery prefers the response's original permalink over a synthetic source-owned URL.

It never copies a parent story owner to unrelated commenters. ## Find UID queue (2026-10-27)

- Added `find-uid` with three workers. ES5 serialization failures specifically caused by an unverified Facebook comment/reply author hand off the complete buzz/source/parent payload to a deterministic Mongo-backed lookup job. Other validation/import errors remain failed for inspection.
- A Mongo feeder archives and transfers existing failed imports to the new queue before removing the old failed tickets. Failed lookup tickets remain failed and are not autonomously retried by that feeder.
- Lookup opens the author's `/pfbid...` profile link through the configured managed proxy. Numeric UID evidence must come from target profile route props, a matching actor URL, or matching canonical/app profile metadata. Conflicting IDs and error/login routes do not become author identities. Missing HTML evidence falls through to anonymous profile route definitions using the same bootstrap response.
- Success stores the response-backed actor identity for future producer mapping and enqueues the updated buzz through normal ES5 validation. A distinct deterministic import job ID prevents a race with removal of the original import ticket. Lookup completion removes the successful lookup ticket; import completion removes its own ticket.
- Lookup uses the initial request plus up to 50 proxy retries; exhaustion keeps `FACEBOOK_UID_RETRY_LIMIT_EXHAUSTED` failed. Existing crawler queues retain their agreed complete/remove exhaustion behavior.
- All current flow workers persist a hashed failed proxy endpoint in the retry checkpoint. The manager excludes that endpoint on the next acquisition, and the HTTP executor independently refuses a repeated endpoint. Pool waits do not consume HTTP retry budget. Removed the hidden same-proxy GET network retry. Proxy identity excludes credentials, so switching accounts on the same endpoint is not counted as a rotation.
- Lookup raw response samples are gzipped in `flow_uid_response_samples`, with a seven-day TTL. Only profile URL/response data is stored, without proxy credentials or authentication headers.
